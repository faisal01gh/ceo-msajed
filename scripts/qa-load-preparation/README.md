# Owned QA HTTP runner

## Execute the local acceptance fixture

```bash
node --require ./offline-network-guard.cjs --test runner.test.mjs
node --require ./offline-network-guard.cjs verify-local.mjs
```

No packages or install are needed (Node built-ins; exercised on Node v26.7.0). The verifier runs the complete suite twice, then independently records another actual loopback HTTP exercise. All writes stay in this directory. `REPORT.json` is the compact receipt; `MEASUREMENTS.json` preserves each measured request lifecycle without headers, tokens, passwords or response payloads. `verification.txt` is actual test output; all source/artifact hashes are SHA-256 of exact file bytes.

## What the local fixture proves

* 50 distinct synthetic UID/SID pairs, authenticated by 50 distinct opaque in-memory tokens and a per-instance loopback challenge. These are NOT native Auth identities.
* HTTP handshake and readback bind the exact listening address/port, run and challenge digest. No DNS names or alternative network targets are admitted.
* Ramps are 50, 250, 500 and 1250 actual load requests. Final is separately 50 identities × 50 HTTP requests = 2500. Capacity control is another separate 2500-request workload with a seven-socket agent; it must report a transport peak no greater than seven while preserving all 2500 completions.
* In the barrier fixture, the actual server withholds responses until all requests arrive. Client `ClientRequest.finish` events measure the socket write/flush boundary, independent of Promise creation. Server receipt/overlap/readback independently proves 2500 actual received requests, distinct request IDs, 50 requests per identity, peak 2500 and full drain.
* Windows' loopback accept backlog rejected a one-tick connection burst in the initial experiment. Local mode now waits for actual server receipt after each 50 newly admitted requests, WITHOUT waiting for responses: pending transport count grows all the way to 2500. This is admission batching, NOT concurrency 50. Release-window width is measured. Native mode has no fixture barrier or local admission acknowledgement and releases all requests without pacing.
* Per-request deadlines start before socket/queue admission; body deadline is absolute from headers, not refreshed by trickle bytes. Round deadline and bounded drain are separate. A sent read with no completely consumed body remains uncertain; closing a local socket does not claim server cancellation.
* Average/min/max and nearest-rank p50/p95/p99 come from measured admission-to-terminal durations, including terminal errors. Terminal and successful throughput use the measured full round window. Raw records allow independent recomputation. Local final percentiles are independently recomputed using indices 1249, 2374 and 2474.
* Seven-role journeys exercise fixture login, forced gate, synthetic password-change session rotation, effective fixture permissions, own visibility, allowed/denied reads, notifications and logout. This is a purpose-built HTTP fixture, NOT execution of product handlers, deployed browser/UI, PostgreSQL or native Supabase.

## Later native phase — locked, not executed here

`native.mjs` exports `runNativeLoad(inputs)` for the parent process. Running `node native.mjs` exits 2 without any network. There is deliberately no credential-file/env/CLI parser, login, refresh, provisioning, deployment, provider setting change or cleanup mutation command.

The parent imports the module and supplies **process-memory-only** `identities` and the separately reviewed `trust`, `approval`, and `attestation` objects. Do not print or serialize these inputs. Both approval and target receipts are Ed25519 envelopes `{payload, signature}` over exact `JSON.stringify(payload)` bytes. The parent must pin the real independent review authority's public key out of band: a key generated by the runner/test is NOT review authority. Local signature fixtures never create or persist an operational approval.

Required approval: `purpose=native-qa-load`, `gate=APPROVED`, `independentReviewer=true`, exact current `sourceSHA`, approved runtime hashes, bounded issued/expiry times, and immutable independent isolation evidence digest. Approval and attestation must remain valid through a request round plus drain. `native.mjs`, `gate.mjs`, `transport.mjs`, `metrics.mjs` exact source hashes are checked again from disk before any network.

Required fresh target receipt: exact `movzojtnkkmdsjhmlgtq`, frontend `https://ceo-msajed.pages.dev`, backend `https://movzojtnkkmdsjhmlgtq.supabase.co`, matching deployed source SHA/run/isolation digest, capture within five minutes, exact protected 57 staff plus legacy eight manual QA UIDs, `faisalUID` inside the protected staff set, stable protected-state digest, reviewed read-only list action, and 50 unique immutable own creation + official persisted-GET + native session readback receipts. Exact-key ownership, native run manifests, canonical aliases, current phase/members and session validity must be reconciled by the parent; a QA prefix is never sufficient proof. No protected identity is allowed into credentials or cleanup.

Each owned load identity must supply `{uid,sid,runId,kind:'owned-load-qa',accessToken,apiKey}`. UID/SID must be unique UUIDs; access JWT claims must match UID, SID, issuer and authenticated role with sufficient remaining lifetime. JWT decoding is not authenticity proof: signed native Auth and session readbacks are compulsory. API key must be public publishable/anon, never service-role or secret. Load identities are separate from seven role-journey canaries and from protected legacy QA.

Read transport is fixed to `POST /functions/v1/transactions-api` with `{action:'list',app:'new',token:<memory-only>,page:1,page_size:10,tab:'all'}`. This exact POST performs reads in inspected main (identity lines 127-164 and list lines 559-587); GET on the function is only a health response and cannot substitute for the list. Native 2xx bodies must contain an array `rows` and matching `me.user_id`. Response bodies are consumed in memory and never persisted. No arbitrary action/route, retry, automatic refresh, redirect follow, reduced final count or arbitrary concurrency-50 policy is provided.

Provider 429/5xx, network/identity errors or uncertain reads stop the next ramp; the already admitted round drains with its exact observed counts. A partial native workload is NOT acceptance. Native final requires 2500 transmitted/body-complete/terminal records, exactly 50 each per UID, zero errors/uncertainty, measured peak 2500 (conservative criterion; no unapproved lower tolerance), and zero retained client handles. A faster native service may produce a smaller peak even with correct dispatch; report it, do not synthesize concurrency or rerun to evade a limit.

`JOURNEYS.json` and `CLEANUP_PLAN.json` specify pending native browser/API/authorization and exact inventory/readback work. `cleanup.mjs` is a pure fail-closed inventory planner/readback validator, NOT a provider mutation executor. Native E2E requires actual product UI, deployed endpoints, current grants/custody and protected snapshots; fixture success is insufficient.
